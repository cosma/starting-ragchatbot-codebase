Course Materials Assistant — backend request lifecycle

From a typed question to a cited answer: how one request moves through session memory, a two-call round trip with Claude, and a filtered ChromaDB search — before rendering back in the chat window.

Why the round trip is capped at one search

AIGenerator._handle_tool_execution() in ai_generator.py only ever makes one extra call after a tool_use response — it executes whatever tools Claude requested, then calls the API again without passing tools. Claude has no way to ask for a second search on that turn, even if the first result was ambiguous or covered only one of two courses a question compared.

The system prompt reinforces the same limit in words — "One search per query maximum" — so the constraint is enforced twice: once as an instruction Claude is trusted to follow, and once structurally, since the second API call has nothing to call even if it tried.
